# The layer map

The "misses" column is load-bearing: it names the next layer that covers the gap, so no layer can
be argued into doing another's job. Gate marks: [MERGE] required on every PR; [RELEASE] real on
`main` and release branches, no-op on PRs; [NIGHTLY] scheduled, informational but never tolerated
red.

| #   | Layer                                                                 | Pins                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Catches                                                                                                                                                                                            | Misses → covered by                                                                                                                                                                                                         |
|-----|-----------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| L0  | Registry closure [MERGE]                                            | The function set is closed in both directions: the registry macro proves membership at compile time; a source scan proves nothing declares a kernel entry outside it.                                                                                                                                                                                                                                                                                                                                                                                                                                              | A function added to dispatch but not to the registry; a registered function with no determinism class, state class, oracle entry or fixture family                                                 | Whether the function is *correct* → L1–L6                                                                                                                                                                                   |
| L1a | Primitive units [MERGE]                                             | Every Tier 0–5 primitive has its own translation unit, its own table-driven tests against hand-derived or externally-derived values, and its own invariant properties, exercised *directly* — never only through a registry function. The per-primitive contract is in the primitive fence in `docs/testing/primitives.md`.                                                                                                                                                                                                                                                                                       | A wrong threshold, a wrong edge comparison, a wrong bucket boundary, a non-associative merge — attributed to the primitive, not to whichever function happened to expose it                        | Whether the primitives compose into the reference's answer → L1b, L2                                                                                                                                                        |
| L1b | Function composition units [MERGE]                                  | Table-driven tests per registry row on hand-derived sequences: every branch of the fold + edge pipeline, single-sample, two-sample, NaN and Inf at first/last, each fixture family the row declares.                                                                                                                                                                                                                                                                                                                                                                                                               | A registry row wired to the wrong primitive or with the wrong plug (a gauge fold given the counter reset predicate); off-by-one in composition                                                     | Shapes the author did not think of → L3, L9                                                                                                                                                                                 |
| L1c | Tier integration [MERGE]                                            | Seam tests between adjacent tiers where the contract crosses an ownership boundary: buffer → window walk, fold → extrapolate, state → host combine, histogram struct → DuckDB struct vector. Each seam has a named contract and a sentinel-driven test (see the seam table).                                                                                                                                                                                                                                                                                                                                       | A primitive that is correct alone and misused by its caller: a view that outlives its buffer, a partial that is merged before it is sorted, a combine that finalises                               | End-to-end numerics → L2–L6a                                                                                                                                                                                                |
| L2  | Reference-derived fixtures [MERGE]                                  | Language-neutral fixture files — samples, grid, window, mode, expected values, provenance — checked into the kernel and replayed against every function. The values were derived by external tools from upstream corpora and live references; the kernel sees only numbers and a provenance string. Rostered by fixture identity; a sync test fails when a derivation source publishes fixtures the roster lacks.                                                                                                                                                                                                  | Any divergence from the reference's function semantics, including histogram rate and staleness, without the kernel knowing what a reference is                                                     | Grids and windows the upstream corpus never sweeps; combine behaviour (references are single-threaded) → L3, L4; cancellation inside a `SUM_ABS` fold, which the scaled bound cannot see → L1a                              |
| L3  | Independent oracle + property sweep [MERGE]                         | A from-scratch evaluator (Python or C++, forbidden from including the kernel) over in-memory series; RapidCheck/FuzzTest sweeps of generated series × grids × windows × modes; an exact ShapeID roster with one deterministic live example per shape; the eval-instant sweep `T ∈ {0,15,30,60,90,120,180,300}s` off the sample clock.                                                                                                                                                                                                                                                                              | Grid-anchor bugs at offsets like 60/90; alignment bugs where step is not a multiple of scrape interval; empty-window agreement                                                                      | Reordering across threads → L4; the reference's real behaviour where the oracle is wrong too → L6; constants (the 1.1× threshold, the half-interval, smoothing seeds) — no relation constrains them, only fixtures → L1, L2 |
| L4  | Partition and determinism [MERGE]                                   | For every function: `f(all)` versus `merge(f_state GROUP BY rowid % N)` for `N ∈ {1,2,3,7,64,4096}`, under `SET threads ∈ {1,2,4,8}`, `PRAGMA verify_parallelism`, a separate `STANDARD_VECTOR_SIZE=2` build lane (sqllogictest's `require vector_size` is a gate, not a setting), shuffled row order, and an explicit adversarial combine order (reverse, interleaved, one-sample partials). `D0` functions compared bit-exact; `D1` within bound.                                                                                                                                                                | Combine that finalises partials; order-dependent state; races in combine (under TSan); a `D0` claim that is false                                                                                  | Whether the single-partition answer is right → L2, L3                                                                                                                                                                       |
| L5  | sqllogictest suite [MERGE]                                          | DuckDB's own harness: types, NULL/NaN literals, `statement error` for bad grid or window arguments, labelled query pairs for equivalences, `foreach` over types and thread counts. The runner's free optimizer-disabled re-run is an extra differential.                                                                                                                                                                                                                                                                                                                                                           | Binding and type-resolution bugs; error-message contract; LIST output shape; behaviour through the SQL surface rather than the C++ API                                                             | Numerics beyond spot values → L2–L4                                                                                                                                                                                         |
| L6  | Provenance refresh [RELEASE]                                        | The external derivation tools re-run against their live references (a real Prometheus over remote-write, with a template-expanded matrix of function × window × offset × step × mode) and re-emit the L2 fixture set; the kernel's release gate ingests the fresh set and applies the L2 roster verdicts. The kernel never talks to the reference; it consumes the derived files.                                                                                                                                                                                                   | Semantics the static corpus does not pin (lookback on real scrape cadence, anchored/smoothed paths, real staleness markers); a reference that changed behaviour in a new version                   | Shapes outside the seeded fixture → L3, L9                                                                                                                                                                                  |
| L6a | SQL-substrate differential [MERGE] (chDB) · [RELEASE] (Timescale)   | The same fixture table loaded into DuckDB, chDB and a Timescale container; the same grid requested from each through its *own* SQL functions — no query language anywhere — and the arrays compared under the one comparator, per oracle through a closed enum of declared divergences. Rostered by (fixture, oracle) identity.                                                                                                                                                                                                                                                                             | Semantic drift on the counter, instant and stats families against two implementations with no shared code; the class of bug where the reference-derived fixtures and the kernel are wrong together | Reductions and histograms Timescale/ClickHouse do not expose → L2, L3; grid semantics they lack (built by the harness) → L3                                                                                                 |
| L7  | Histogram oracles [MERGE]                                           | Prometheus `float_histogram_test.go` tables (Add, Sub, Compact, DetectReset, schema reduction) ported verbatim as fixtures; OTel `exponential_histogram_test.go` value→index vectors and the `FuzzGetBin` invariant; UDDSketch collapse equivalence; scale mix `{−1,0,1,2}` in every merge test.                                                                                                                                                                                                                                                                                                           | Wrong bucket geometry, wrong zero-threshold reconciliation, merge not associative under schema downgrade, exponential-vs-linear interpolation                                                      | Histogram rate on a grid → L2 (native_histograms.test), L3                                                                                                                                                                           |
| L8  | Cross-path proof [MERGE]                                            | Every implementation of a function agrees on deterministic datasets engineered so a specific bug returns a specific wrong number: the SQL-macro reference (ASOF JOIN + `list_aggregate`), the aggregate form, and — registry-driven, for every `RANGE`/`HIST` row — the operator, bit-exact for `D0`. The operator also has its own L4-style roster: threads {1,2,4,8}, `preserve_insertion_order` on and off, the vector-size-2 build, shuffled and reverse-sorted input, and a partition that splits one series across two morsels. The duplicate-timestamp counter (correct 50, wrong 37.5) is the first entry. | A fast path diverging from the slow path; a bug that only one path has                                                                                                                             | Bugs all three paths share → L2, L3, L6                                                                                                                                                                                     |
| L9  | Fuzz + sanitizers [NIGHTLY] (ASan/UBSan on [MERGE])              | Grammar-aware SQL fuzzing over the loaded extension with statement-reduction for repros; structured fuzzing of `Series{samples, grid, window, split_points}` asserting the metamorphic relations; corpus seeds from every L1 and L3 fixture.                                                                                                                                                                                                                                                                                                                                                                        | Crashes, UB, overflow, pathological argument combinations, MR violations on shapes no generator enumerated                                                                                         | Correctness of non-crashing answers → L2, L3                                                                                                                                                                                |
| L10 | Mutation [NIGHTLY], diff-scoped on PRs                              | A mutation-testing runner over the kernel TUs with L1+L3+L4+L5 as the runner; per-TU efficacy floor 95%; kill-test files per surviving mutant cluster; documented-equivalent footers under the 5% ceiling.                                                                                                                                                                                                                                                                                                                                                                                                          | Boundary flips (`<`↔`<=`) in reset detection, window edges, extrapolation threshold; dead assertions                                                                                               | Missing behaviour (a mutant cannot add a feature) → L2, L6                                                                                                                                                                  |
| L11 | Memory and scale sentinels [RELEASE]                                | Tracked state bytes per state class against its law (`threads × window` for the operator); peak buffer memory and RSS reported beside it; serialised `_state` bytes; the aggregate form's O(range) cost measured and documented; fan factor (intermediate rows ÷ scanned rows) ratcheted per shape; wall-clock diff reported weekly.                                                                                                                                                                                                                                                                              | Unbounded buffering; combine that copies instead of moves; a state class that lies about its size                                                                                                  | Wall-clock regressions on PRs (weekly only) → accepted                                                                                                                                                                      |
| L12 | Multi-provenance fixtures [RELEASE]                                 | The L2 fixture set must carry at least three distinct provenances per function family — for example a metrics reference, a trace engine's duration-valued metric tests and a log engine's count-valued ones, all derived externally into the same neutral format. A function whose fixtures all share one provenance fails a floor test.                                                                                                                                                                                                                                                                           | A single reference's blind spots; assumptions about the value domain (counters only, non-negative only) leaking into the surface                                                                   | Wire formats, parsers — out of scope by design                                                                                                                                                                              |
| L13 | Meta-tests on the testing itself [MERGE]                            | Enrollment evidence (T6); inert-fixture detection (a fixture with samples but no expected value); registry↔case-list closure (T1); citation resolution (T12); forbid-skip (T2); forbid-consumer (T14); ratchet-file schema; lane registry ↔ workflow binding; the mutation scoring monotonicity pin; the comparator headroom pin.                                                                                                                                                                                                                                                                                  | The test suite rotting: a lane that runs nothing, a roster that shrank, a tolerance that widened                                                                                                   | Nothing about the kernel; that is the point                                                                                                                                                                                 |
| L14 | Public-surface end-to-end [RELEASE]                                 | The signed extension `LOAD`ed into a stock DuckDB binary and the Python client (never linked into a test executable), over a persisted `.duckdb` file, a Parquet directory and, when stable, the RawDuck OTLP path; a generated devops-style dataset at ~100k series with realistic cadence and resets; the full registry surface driven through SQL and diffed against chDB on the same data; the L11 sentinels and the memory self-check run inside this lane.                                                                                                                          | Packaging and loading faults; behaviour that differs between test harness and product binary; scale-only failures (spill, RSS, rows scanned); a bounding mechanism whose sentinel no longer fires  | Nothing below the SQL surface — everything above; and PR-time wall-clock, which stays weekly                                                                                                                                |
| L15 | Storage partners [RELEASE]                                          | `docs/testing/storage-partners.md`'s contract: the partner stores, chronoduck computes; the integration surface is ordinary pushed filters, a profile, at most one view, and the serialised-state contract — nothing partner-specific under `src/`. `scripts/partners/rawduck.json` pins the first partner (RawDuck) by commit; `make partner-rawduck-build` fetches it into `build/partners/rawduck/` (never a submodule) and builds it against *this repo's own* pinned DuckDB tag, cached by (partner commit, our pin); `make partner-rawduck-test` LOADs both `.duckdb_extension` files into one stock DuckDB shell and runs `test/partners/rawduck/*.sql` (not `*.test` — DuckDB's own sqllogictest runner would otherwise auto-discover and misparse it). The nightly `partner-rawduck-head` lane runs the identical two `make` targets with `RAWDUCK_REF=head`, building and testing RawDuck's own default-branch HEAD instead of the pin, to surface upstream drift before it silently breaks compatibility. | Both extensions failing to LOAD together (symbol or catalog conflict); the partner failing to build at chronoduck's own DuckDB pin; drift between the pinned partner commit and what's actually checked out; RawDuck's own HEAD drifting into an incompatibility (nightly, `partner-rawduck-head`) | Real fixture-driven layout-parity testing against RawDuck's actual on-disk layout (T2.10) |
